The server synthesises the file on request — a header, a hole of zeros, and every object in the last few KB — so nothing is written to disk. The reader pulls only the byte ranges it needs, so a 4 GiB file still costs a few hundred KB and a flat heap.

A 4 GiB PDF cannot fit in wasm32's address space, so the heap was never the answer — offsets were. Each xref entry here lands above 2³² − 1 MiB, which is where 32-bit offset bugs show up.
