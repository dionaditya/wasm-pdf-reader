notices in place.

## Embedded substitute faces

`src/cpp/fonts_data.h` carries eight metric-compatible font families as C byte
arrays so that a PDF which does not embed its font still lays out with the right
advances (Arial → Liberation Sans, Calibri → Carlito, Cambria → Caladea, …).
Each face is **subset to WinAnsi + Latin-1 + typographic punctuation**, which makes
it a Modified Version under the OFL: the full licence text travels in
`LICENSES/`, and the copyright lines are in the table above.

The subsets keep their upstream family names inside the font's `name` table. That
is fine for matching and for the OFL's "do not sell the font by itself" clause,
but it is not what the Reserved Font Name clause wants for a Modified Version —
renaming the internal tables to `Wpdf Sans`/`Wpdf Serif`/… is the strict fix and
is listed as an open item in `ROADMAP.md`. Nothing here renames the fonts on disk
or ships them as installable faces.

## Notes

- The CFF *interpreter* (`src/cpp/cfffont.cpp`) is first-party; only the
  standard-string and encoding tables come from nanopdf.
- `src/cpp/jbig2gen/jbig2.c` is generated by `wasm2c` from the wasm binary that
  `mozilla/pdf.js.jbig2` builds out of PDFium's `core/fxcodec/jbig2` and
  `core/fxcodec/fax`. It is compiled into `pdf-reader.wasm`; `simde/` and
  `wasm-rt-*.c` are the runtime support that generated code needs (wabt BSD-2,
  simde MIT). Regenerate with `wasm2c jbig2.wasm -o jbig2.c` **and re-apply the
  provenance header** at the top of the file (wasm2c emits only
  `/* Automatically generated by wasm2c */`).

## Vendored vs first-party, by size

The engine is a small first-party core around large vendored decoders. Line counts
(`wc -l` over `src/cpp`, excluding comments-free estimation):

| Part | Lines | Share |
|---|---|---|
| `simde/` (MIT) | 257,515 | 51 % |
| `jbig2gen/jbig2.c` (generated from PDFium, Apache-2.0) | 54,232 | 11 % |
| `cmaps_data.cpp` (generated data, Adobe BSD-3) | 54,941 | 11 % |
| `openjpeg/` (JPEG 2000, BSD-2) | 55,159 | 11 % |
| `fonts_data.h` (font binaries, OFL/Vera) | 38,789 | 8 % |
| `pdf_glyphs.h` / `pdf_widths.h` (generated metrics) | 21,556 | 4 % |
| `stb_image.h`, `stb_truetype.h` (MIT/PD) | 13,067 | 3 % |
| nanopdf CFF tables, CCITT, wabt runtime | 4,299 | 0.9 % |
| **first-party** (`pdfdoc`, `pdfraster`, `wpdf_api`, `pdfannots`, `cfffont`, `cmap`, `jbig2native`, `jpxopenjpeg`, headers) | **~4,650** | 0.9 % |

That ratio is deliberate: nobody should hand-write a JBIG2 arithmetic decoder or
SIMD polyfills. What is first-party is the part no library offered — the PDF object
model, the content-stream interpreter, the rasterizer, the font machinery and the
CMap logic — and it is the part every bug in `ROADMAP.md` is about.
